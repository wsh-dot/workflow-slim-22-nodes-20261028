# 区分失败续跑与整批重新执行，按环节替换料表成果

本记录依据2026-11-03用户给出的最新业务说明，随grill-with-docs访谈收敛；Q1至Q7业务规则已由用户确认。文档保留草案状态，业务确认不代表代码已实施或已通过运行验收。最新说明优先于旧验收假设与ADR-0002/0003中“永不替换已有结果、失败必须创建新任务”等历史约定；0/1状态和错误信息区分终态的核心约定继续保留。

## 已明确的业务规则

| 动作 | 文件范围与处理含义 |
|---|---|
| 正常下一步 | 发起目标下一环节任务，将当前批次料表设为该环节待处理 |
| 失败后再次下一步 | 将失败任务恢复为未结束，保留已成功料表，只处理尚未完成的料表 |
| 明确重新执行 | 将当前批次全部料表设为指定环节待处理，包括此前成功文件 |

Python依次处理待处理料表，单份成功后标该环节完成。全体待处理料表成功后任务结束且错误为空；第6份失败时前5份成功结果保留，任务结束并保存错误。任务未结束为0，成功或失败结束为1。重启Python服务后Runner应自动工作。

界面使用的基本验收条件同时包含两条路径：新建项目准备CBS并上传料表后正常发起工程量；已有项目在当前可编辑批次继续上传料表后也能发起工程量处理。两条路径均使用同一正常常驻Runner，不登记项目或批次ID，不逐任务重启Python。已有工程量的批次追加后按明确重新构建规则整批重算，包含旧文件和新文件，不另行默认为只解析新增文件。进入概算计算后批次固定的规则继续保留；高阶段流程退回仍按Q7暂缓事项记录。

工程量环节替换范围为sc_file_item、sc_file_item_match、sc_file_item_match_consume、sc_file_item_match_relation；定额/指标匹配环节替换后三张表；价格匹配更新sc_file_item_match和sc_file_item_match_consume的价格。这里列的是业务影响范围，不是已验证的SQL删除顺序。
