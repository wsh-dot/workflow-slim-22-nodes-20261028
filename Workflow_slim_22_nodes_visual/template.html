画布边界与责任

AI 服务：冻结执行配置、派发和领取、保存阶段检查点、发起一次纠正新运行、监控异常并有界恢复、发布完整结果。

Java：异步提交并通过结果接口取回完整 tree、cbsMatch、rowDispositions、issues，按文件版本与权限校验后短事务入库。

这两项责任均在 Dify 画布之外；End 仅返回身份，不代表业务完成。

三个不能混用的身份

task_idstreaming 中实际取得；配合原 user 停止任务。
workflow_run_idDify 实际运行身份；查询运行、领取和防重复执行。
workflow_id固定已发布 Workflow 版本；与 execution_config_id 一起约束首轮、纠正和恢复。

画布之外：纠正与失败恢复

运行 1：结构提交保存 REPAIR_REQUIRED → RETURN → End。AI 服务：确认运行结束后，在同一 file job / buildGeneration 和固定执行配置下创建新 dispatch。运行 2：以 STRUCTURE_REPAIR 入口再次使用结构模型，最多纠正一次；合法后进入 CBS。两次运行分别拥有实际运行身份。

CBS 失败：技术异常使 run 失败；服务核查持久检查点并有界恢复，耗尽且存在合法结构时发布完整树及未挂接结果，cbsMatch.executionStatus=FAILED。来源树质量决定 semanticStatus。Java 后台通过 GET /smartCost/ai/quantity/jobs/{jobId}/files/{fileId}/result 取回完整结果。

匹配顺序：先按单位工程名称保留全部 match / possible 候选，再用相同完整表头、专业和内部章节比对候选直接父节点。唯一且符合条件时挂单位工程叶子；未匹配统一归入现有“未挂接”。

可选：三个序列化节点

仅在模型插件没有完整 text、但有完整 structured_output 时分别添加，全部使用时共 25 节点；不属于上方 22 个核心节点。服务应标记原始模型文本不可得，不能把序列化结果称作原文。

sBuildProcessBody：sLLM → sProcess；qBuildLeafBody：qCbsLeafLLM → qCbsLeafValidate；qBuildParentBody：qCbsParentLLM → qCbsParentValidate。输入 model_output（Object）绑定对应 structured_output，输出 request_text（String），HTTP raw body 改绑 request_text。
