## 已完成的改动

本次新增业务表只保留`sc_file_analysis_snapshot`。执行版本改存现有`sc_ai_python_task.execution_profile` JSONB字段，Python正常运行已不再访问`sc_0902_execution_profile`、`sc_0902_optimization_control`或禁用代次触发器。

1. 新任务的执行字段初始为SQL NULL。首次执行在任务行锁内记录源码、模板、模型配置、业务规则及CBS指纹，并保存版本正文、任务归属和冻结时间。记录不包含明文模型密钥，也不作为模型输入。
2. 同一任务续跑、模型调用及结果提交继续复核请求身份和执行版本。更换request_id不解除task_id的版本限制；正文与指纹不一致、源码变更或任务归属变化时拒绝运行或提交。
3. 结果保存仍使用原单文件事务：替换`sc_file_item`、清理相关下游引用、追加快照及更新文件2102状态一起提交。任一保存失败全部回滚。失败续跑保留此前成功文件和人工修改。
4. 历史禁用信息改存任务JSON，删除源码中针对本库59个历史task_id的硬编码名单。`FROZEN`和`RETIRED`只是执行记录内部状态，任务原0/1状态不变。
5. Java任务实体和接口无需增加映射；新增字段由Python维护。本次未修改Java、前端或0903业务代码。
